# HISS Standard v1

Hospitality Information Security Standard for hotels. Author: Raghunath Thiyagarajan.

This file is generated by render_standard.py from the catalogue files. To change the text edit the catalogue and run the tool again.

The catalogue holds 80 controls in 16 domains: 63 Baseline and 17 Enhanced.

## 1 Scope and use

HISS is written to sit on top of an ISO/IEC 27001 information security management system and does not replace it. It is a self assessment framework and not a certification scheme. Obligation entries summarise legal duties as they appear in the fact files and are not legal advice. Standards text is paraphrased: identifiers and short titles are used and control wording from ISO or PCI documents is not reproduced.

## 2 Profiles, requirement levels and triggers

Profile thresholds are the author's judgement. Baseline controls apply to every profile. Enhanced controls apply to the profiles listed on the control. An Enhanced control that does not list the profile becomes mandatory when one of its triggers is active.

| Profile | Name | Description |
|---|---|---|
| S | Single property | One property under about 75 rooms with no dedicated IT staff |
| M | Mid size property | 75 to 200 rooms or a property with shared IT support |
| G | Group or management company | Several properties run with central IT |

| Trigger | Meaning |
|---|---|
| T1 | Stores card data electronically |
| T2 | Uses mobile or online keys |
| T3 | BMS or CCTV on the IP network |
| T4 | Cloud hosted PMS |
| T5 | Guests from a jurisdiction listed in the profile |

Operating models: owned, managed and franchised. Each control names the accountable party for each model as group, property, vendor or franchisee.

## 3 Hotel realities

| Id | Reality | Description |
|---|---|---|
| R1 | Round the clock operation | Front desk, PMS and payments run every hour of every day, so maintenance windows are short and incidents often happen when IT staff are absent. |
| R2 | Seasonal and outsourced staff | Many users are seasonal, agency or outsourced workers who start on a live shift and leave at short notice. |
| R3 | Shared devices | Front desk, outlet and back office terminals are shared across shifts and roles. |
| R4 | Multi property operation | Several properties run under one group with separate directories, uneven builds and local IT support. |
| R5 | Franchise or managed operation | Brand, operator, owner and franchisee split accountability while vendors run many core systems. |
| R6 | Mixed guest data | Card data, identity documents, guest registers, folios, loyalty profiles and CCTV sit in one estate under several legal regimes. |
| R7 | Operational override | Operations teams override IT rules to protect the guest experience when security and service collide. |

## 4 Maturity scale

| Score | Meaning |
|---|---|
| 0 | Not in place |
| 1 | Ad hoc |
| 2 | Documented |
| 3 | Implemented with evidence |
| 4 | Measured and reviewed |

A control counts as met at 3 or above. The scale is the study's own and is only loosely aligned to the NIST CSF tiers.

## 5 Mapping strength

Each crosswalk row carries a strength label. D (direct) means the objectives match, the target is verified and a named source supports the link. The text then says maps to. P (partial) means the target covers part of the control or the control covers part of the target. The text then says maps in part to. J (judgement) is the author's reading with no source support. The text then says judged to relate to.
